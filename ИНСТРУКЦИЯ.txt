Сайт на HTML, CSS, JavaScript и PHP без CMS
Редакция: 19 октября 2026

ЧТО ПОДГОТОВЛЕНО
Лендинг, фильтры услуг, подробные описания в диалоге, обновлённые четыре вопроса FAQ, форма заявки, админка для текстов, цен и фотографий, страницы документов, cookie-баннер, HTTP 404, иконка, Open Graph, Organization, canonical, robots.txt и sitemap.xml.
Дизайн: полноэкранное фото в первом экране с текстом поверх, крупное фото выбранной услуги и переключатели, глубокий зелёный и приглушённое золото. При прокрутке элементы плавно появляются, фон первого экрана слегка смещается. Системная настройка уменьшения движения отключает анимацию. Декоративные ромбы, стрелки и технические подписи убраны. Ссылки в футере — 14 px, с увеличенными интервалами.

ДВА ВАРИАНТА
1. Статическая демонстрация GitHub Pages: внешний вид и интерактивные элементы. PHP на этой площадке не исполняется. Форма готовит письмо в вашей почтовой программе и ясно показывает, что оно ещё не отправлено. Админка находится только в PHP-версии.
2. Этот каталог: полноценная PHP-версия для вашего существующего хостинга. До настройки канала доставки заявки через сервер отключены. Форма никогда не сообщает об успешной отправке, если канал не настроен.

УСТАНОВКА
1. Требуется PHP 8.2+ с mbstring, json, fileinfo, session. Для Telegram также curl и openssl. Сторонние PHP-пакеты и база данных не нужны.
2. Загрузите каталог на сервер. DocumentRoot домена должен указывать СТРОГО на public/. Каталоги app/, data/, scripts/ и config.local.php должны оставаться вне веб-корня. Не загружайте весь проект в public_html без изменения корня домена.
3. Для Apache в public/.htaccess уже настроены маршрутизация, HTTPS и заголовки. Нужны mod_rewrite и AllowOverride. Для Nginx используйте nginx.example.conf, заменив домен, путь и сокет PHP-FPM.
4. У веб-сервера должны быть права записи в data/ и public/uploads/. Не устанавливайте права 777. Рекомендуется владелец процесса PHP и права каталогов 750/755, файлов 640/644 по правилам хостинга.
5. Скопируйте config.example.php в config.local.php. Укажите base_url: реальный HTTPS-адрес без завершающего /. Это включает правильные canonical, OG URL, OG image и sitemap. До указания домена production-версия не подставляет вымышленный адрес.
6. Настройте сертификат HTTPS и проверьте работу перенаправления HTTP → HTTPS. Если хостинг использует обратный прокси, администратор должен корректно передавать в PHP проверенный HTTPS-признак; не доверяйте произвольным заголовкам посетителя.
7. Выполните в терминале сервера: php scripts/setup-admin.php admin
Задайте собственный пароль от 12 символов. В конфигурации сохраняется только хеш. Админка: /admin.php. Нет общего пароля по умолчанию. Если SSH нет, хостер может выполнить CLI-скрипт; открытого веб-установщика нет.
8. Для локального просмотра из каталога проекта: php -S 127.0.0.1:8000 -t public public/router.php

КАК МЕНЯТЬ САЙТ
В /admin.php можно править первый экран, контакты, описание компании, названия и состав услуг, цены и ответы FAQ. Фото JPEG/PNG/WebP до 5 МБ загружаются отдельно для нужного блока или услуги.
Расширенный JSON-редактор содержит отзывы и кейсы. Отзыв должен иметь name, quote, source (HTTPS-ссылка на источник). Кейс: title, description, image (локальный путь /assets/… или /uploads/…). Храните резервную копию data/content.json перед большими изменениями. Добавление услуг требует уникального латинского id и group: home, business, special или их комбинации через пробел.
Сессия админки завершается после 30 минут бездействия. Вход ограничен пятью попытками за 15 минут для одного сетевого адреса. Защита включает CSRF, проверку структуры данных, экранирование HTML и проверку формата загружаемых изображений.

ДОСТАВКА ЗАЯВОК
Почта:
- mail_to уже задана: chistota.v.dome@mail.ru.
- Укажите mail_from: рабочий адрес на вашем домене, разрешённый вашим почтовым сервером.
- Настройте PHP mail()/MTA на хостинге, SPF/DKIM по инструкции почтового провайдера.
- Установите mail_enabled = true и leads_enabled = true.
- Выполните собственную тестовую заявку и проверьте папку «Спам».
Результат mail() означает принятие письма почтовым сервером, а не подтверждение прочтения или гарантированную доставку. Фактическую доставку необходимо проверить на вашем хостинге.

Telegram, если он выбран вместо почты или дополнительно:
- Нужны токен вашего бота и числовой chat_id. Телефон 8 909 703 88 77 не является chat_id.
- Укажите telegram_bot_token и telegram_chat_id в config.local.php, затем leads_enabled = true.
- Не публикуйте токен бота. Перед включением определите и отразите фактические условия передачи персональных данных в документах.
- Посетительская ссылка telegram_url в админке — отдельная настройка, она не настраивает доставку боту.

МЕТРИКА И ВЕБМАСТЕР
metrika_id: [заполнить] — числовой ID счётчика. Цели JavaScript: request_click (главная кнопка/переход к заявке) и lead_sent (только успешная передача серверной заявки). Они должны быть созданы в вашем счётчике.
Метрика загружается только после «Разрешить аналитику»; Вебвизор отключён. Выбор «Только необходимые» не подключает счётчик. Повторно открыть выбор можно в футере. После отзыва разрешения страница перезагружается, дальнейшая загрузка Метрики прекращается. Старые cookie поставщика можно удалить в браузере.
webmaster_verification: [заполнить] — значение meta-проверки вашего домена. После установки добавьте домен и sitemap.xml в Яндекс Вебмастер. Подключение кабинета без ваших доступов не выполнено.
Статическая демонстрация GitHub Pages закрыта от индексации метатегами noindex на каждой HTML-странице и дополнительным robots.txt. У боевой PHP-версии публичные страницы имеют index,follow.

СОПРОВОЖДЕНИЕ
Периодически архивируйте data/content.json и public/uploads/. config.local.php храните отдельно и защищённо. Файлы data/rate-*.json содержат только временные отметки и хеш адреса, их можно удалять при обслуживании. При смене домена обновите base_url. Это новый сайт; таблица старых URL не предоставлена, поэтому внешние 301-переадресации не выдуманы. Канонизация завершающего слеша и HTTP → HTTPS предусмотрена.
